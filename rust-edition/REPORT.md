# Torrent 1.4.0 Rust Edition Preview 1

База — Torrent 1.4.0 (`da84a5b`). В этой сборке Rust обрабатывает сортировку файлов торрента по размеру. Порядок при одинаковых размерах стабильный в обоих направлениях. Индексы файлов остаются привязаны к libtorrent, поэтому сортировка сохраняет выделение и приоритеты.

## Архитектура и применимость rust-anything

| Компонент | Реализация | Решение |
|---|---|---|
| Окна, настройки, диалоги и отрисовка | C++20, Win32, Direct2D, DirectWrite | Сохранены. Для переноса потребовались бы собственные Windows-тесты и полноценная интеграция с Win32. |
| BitTorrent и сохранение сессии | C++ и libtorrent-rasterbar через vcpkg | Сохранены. Замена движка требует отдельной проверки совместимости протоколов, данных и восстановления загрузок. |
| Сортировка по имени | Windows CompareStringEx с резервным CompareStringOrdinal | Сохранена для системных правил сравнения имён и чисел. |
| Сортировка по размеру | Стабильная сортировка индексов | Rust staticlib, один вызов через C ABI на список. Для неполного массива размеров сохраняется текущая ветка C++. |
| Дистрибутив | Штатная версия использует CONNECT Installer и NSIS | Preview предоставляется в портативном ZIP для Windows 11 x64. Он использует существующий профиль Torrent и штатную защиту от одновременного запуска. |

Установлен и запущен rust-anything 2.0.2 из npm. Его анализ определил проект как C и частично разобрал 10 заголовков. Официальная документация описывает C-мост для скаляров и строк, а для этой операции требуются массивы и C++. Поэтому мост реализован вручную, а исходный C++-код записан и проверен через CLI-адаптер командами `rust-anything app record` и `app replay`. Этот прогон охватывает сортировку по размеру. [Документация установки](https://github.com/erkamyaman/rust-anything/blob/main/docs/install.md) · [Документация команд](https://github.com/erkamyaman/rust-anything/blob/main/docs/tools.md)

## Сравнение

| Метрика | Torrent 1.4.0 | Rust Edition Preview 1 |
|---|---:|---:|
| Сортировка 10 000 файлов, медиана 5 прогонов по 200 сортировок | 132,9 мс | 59,4 мс |
| Воспроизведение записанного поведения | 8 эталонных случаев | 8 из 8, включая 64-битные границы и одинаковые размеры |
| Дополнительная проверка порядка | Эталон C++ | 1 024 совпадения на детерминированных массивах двух направлений |
| Размер приложения | Сравнивается с тем же исходным кодом и флагами компилятора | См. Windows-замер в приложении к релизу |
| Оперативная память и время запуска | Измеряются запуском штатного smoke-теста на Windows | См. Windows-замер в приложении к релизу |
| Стабильность | Эталонное поведение | Публикация выполняется после Windows-проверок движка, запуска, позиции окна и настроек. Длительная эксплуатация не измерялась. |
| Сопровождение | CMake, MSVC, vcpkg | Дополнительно Cargo, Rust и одна граница C ABI. Сторонних Rust-зависимостей нет. |

Микробенчмарк Linux сравнивает сортировку вместе с подготовкой массива индексов в обоих вариантах. Ускорение в этом сценарии — 2,24 раза. Это замер конкретной операции. Результаты Windows и размер EXE нужно оценивать по данным той же сборки. Сравнение размеров архивов с установщиком было бы некорректно.
